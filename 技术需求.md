## 3. 核心模块技术需求

### 3.1 知识库构建模块

#### 3.1.1 文档解析服务（v2 重建）

**需求描述**：解析各类文档格式，提取文本 / 图片 / 表格 / 图注，产出统一中间结构 `ParsedDocument`，供下游 RAG + GraphRAG 双路入库。

**输入**：
- PDF（中文教材 / 英文论文 / 扫描版 / 表格密集 / 图文混排）
- Word（python-docx）
- TXT / MD

**PDF 类型检测**（每个 PDF 先判型，再选路）：

| 类型   | 检测方式                         | 处理路径                           |
| ------ | -------------------------------- | ---------------------------------- |
| 文本型 | `fitz` 抽几页判断文字密度 > 阈值 | PyMuPDF 直抽                       |
| 扫描型 | 文字密度 < 阈值                  | OCR（PaddleOCR / GLM-4V 选型待定） |
| 混合型 | 逐页判断                         | 文本页 + 扫描页混跑                |

**处理流程**：
```
┌──────────┐   ┌──────────┐   ┌──────────┐   ┌──────────┐   ┌──────────┐
│ 文档输入 │──▶│ 类型检测 │──▶│ 内容提取 │──▶│ OCR补全  │──▶│ ParsedDoc│
└──────────┘   └──────────┘   │ 文本+图片│   │ (扫描型) │   │  中间结构 │
                             │ + 表格   │   └──────────┘   └──────────┘
                             └──────────┘
```

**统一中间结构 `ParsedDocument`**（上下游契约）：
```json
{
  "doc_id": "doc_001",
  "source_path": "raw-docs/材料科学基础.pdf",
  "sha256": "...",
  "metadata": {
    "title": "材料科学基础",
    "authors": ["XXX"],
    "year": 2020,
    "language": "zh",
    "parser_version": "v2.0",
    "pdf_type": "text"
  },
  "pages": [
    {
      "page_num": 45,
      "text": "晶体结构是材料科学的基础...",
      "blocks": [{"bbox": [x0,y0,x1,y1], "text": "...", "type": "text"}],
      "images": [
        {
          "image_id": "img_001",
          "bbox": [100, 350, 400, 600],
          "caption": "面心立方晶胞结构图",
          "mentions": ["如图3-1所示", "图3-1展示了..."]
        }
      ],
      "tables": [
        {
          "table_id": "tbl_001",
          "caption": "表3-1 常见晶格类型",
          "rows": [["FCC", "面心立方", "Al/Cu/Ni"], ...]
        }
      ]
    }
  ],
  "images_needing_caption": []  // 无图注的图片，后续调 GLM-4V 生成
}
```

**技术选型**：

| 功能       | 工具/库                    | 说明                               |
| ---------- | -------------------------- | ---------------------------------- |
| 文本提取   | PyMuPDF (fitz)             | 按 block 排序，保留阅读顺序        |
| 图片提取   | PyMuPDF                    | 抽字节 + bbox + 关联图注正则       |
| 表格提取   | pdfplumber                 | 抽 CSV-like + 表注                 |
| 扫描 OCR   | 待定（GLM-4V / PaddleOCR） | 选型标准：中文识别率 / 限流 / 成本 |
| 无图注描述 | 智谱 GLM-4V                | 限流 + 3 次指数退避                |
| Word解析   | python-docx                | 同样输出 `ParsedDocument`          |

**统一 API**：
- `POST /api/v1/documents/parse/pdf` → 完整 `ParsedDocument`（含图片/表格）
- `POST /api/v1/documents/parse/pdf/text` → 只取文本（快路径，给 GraphRAG 跑 `graphrag index` 用）

#### 3.1.2 向量嵌入服务（RAG 通道独立设计）

> **架构定位**：上游 `ParsedDocument` 产出后，**RAG 通道独立做分块 + 向量化**（不再依赖 GraphRAG 的自动处理）。
> GraphRAG 通道另外维护 `entity_embeddings` collection（见 3.1.3）。

**需求描述**：把 `ParsedDocument.pages[].text` 切成 chunk → 调智谱 embedding-3 → 写 Milvus + PG。

**技术要求**：

| 项目           | 选型                                       | 说明                             |
| -------------- | ------------------------------------------ | -------------------------------- |
| Embedding 模型 | 智谱 `embedding-3`                         | 全平台统一                       |
| 向量维度       | 2048                                       | 与 GraphRAG 通道保持一致         |
| 分块器         | LangChain `RecursiveCharacterTextSplitter` | 句子级优先 + 长度兜底            |
| 分块参数       | chunk_size=512, overlap=64                 | 经验值，先固化再调优             |
| 批量化         | `ZhipuService.batch_embed` + 限流          | `time.sleep(0.3)` + 3 次指数退避 |

**处理流程**：
```
ParsedDocument.pages[].text
  → 文本清洗（去页眉页脚 / 去空行）
  → RecursiveCharacterTextSplitter (512/64)
  → 批量 embed
  → Milvus `chunks` collection (IVF_FLAT, nlist=1024, COSINE)
  → PG `chunks` 表 (id / doc_id / page_num / text / milvus_id)
```

**Milvus `chunks` collection schema**：

| 字段        | 类型               | 说明                 |
| ----------- | ------------------ | -------------------- |
| chunk_id    | VARCHAR(64)        | 主键，与 PG 双向指针 |
| doc_id      | VARCHAR(64)        | 文档 ID              |
| page_num    | INT                | 所在页码             |
| text        | VARCHAR(4096)      | 原文片段             |
| embedding   | FLOAT_VECTOR(2048) | 智谱 embedding-3     |
| source_path | VARCHAR(512)       | MinIO 路径           |

**幂等性**：按 `(doc_id, chunk_id)` 去重，重复入库向量不变。

### 3.2 Agent智能问答模块

#### 3.2.1 Agent架构设计

**架构模式**：**LLM 意图路由 + 双路 RAG/GraphRAG 融合**

```
┌────────────────────────────────────────────────────────────┐
│                      User Query                             │
│   "什么是马氏体相变？" / "FCC 和 BCC 的区别有哪些联系？"    │
└────────────────────────────────────────────────────────────┘
                            │
                            ▼
┌────────────────────────────────────────────────────────────┐
│              【LLM 意图路由】（阶段三核心调度器）            │
│    ┌─────────────────────────────────────────────────────┐ │
│    │  路由 prompt：                                       │ │
│    │  "判断用户问题是查事实类还是关系/总结类，返回 JSON"   │ │
│    │  - 查事实类 → channel: "rag"                         │ │
│    │  - 关系/总结类 → channel: "graphrag"                 │ │
│    └──────────┬──────────────────────────┬───────────────┘ │
└───────────────┼──────────────────────────┼─────────────────┘
                ▼                          ▼
┌────────────────────────┐    ┌────────────────────────────┐
│   【RAG 通道】         │    │   【GraphRAG 通道】         │
│   查事实 / 找原文段落  │    │   找关系 / 做总结          │
│                        │    │                            │
│   Milvus `chunks`     │    │   1) 实体 mention 抽取     │
│   向量召回 top-k       │    │   2) PG `entities/rels`    │
│   → 智谱 rerank        │    │      1-2 跳子图            │
│   → 构造 chunk 上下文  │    │   3) Milvus                │
│                        │    │      `entity_embeddings`   │
│                        │    │      取描述补全            │
│                        │    │   4) 社区摘要（可选）      │
└───────────┬────────────┘    └────────────┬───────────────┘
            └────────────┬─────────────────┘
                         ▼
┌────────────────────────────────────────────────────────────┐
│              Response Generation（统一封装）                │
│   输入：检索到的 `Doc` 列表 + 路由决策                      │
│   输出：`{answer, sources: [{type, ref, snippet}],         │
│          channel_used: "rag"|"graphrag"}`                  │
└────────────────────────────────────────────────────────────┘
```

**为什么用双路而不是单一 RAG**：
- 查事实类（如"什么是马氏体相变"）：原文段落信息最准，走 RAG 通道即可
- 关系/总结类（如"FCC 和 BCC 的区别和联系"）：需要跨段落聚合 + 实体关联，走 GraphRAG 通道
- LLM 先分类再调对应通道，避免 GraphRAG 在简单问题上浪费成本，也避免 RAG 在复杂问题上答不全

#### 3.2.2 检索策略（双路 + 统一 Retriever 接口）

**统一 Retriever 接口**：
```python
class Retriever(Protocol):
    def retrieve(self, question: str, top_k: int = 5) -> list[Doc]: ...

class Doc:
    channel: str            # "rag" | "graphrag"
    doc_id: str
    page_num: int | None
    snippet: str
    score: float
    ref: dict               # chunk_id / entity_id / relationship
```

**RAG 通道实现**：
```python
class RAGRetriever:
    def __init__(self, milvus_chunks, reranker):
        self.milvus = milvus_chunks
        self.rerank = reranker

    def retrieve(self, question: str, top_k=5) -> list[Doc]:
        # 1) Milvus `chunks` 向量召回 top-20
        hits = self.milvus.search(question, k=20)
        # 2) 智谱 rerank
        reranked = self.rerank.rerank(question, hits, top_k=top_k)
        # 3) 构造 Doc 列表
        return [Doc(channel="rag", doc_id=h.doc_id, page_num=h.page,
                    snippet=h.text, score=h.score, ref={"chunk_id": h.id})
                for h in reranked]
```

**GraphRAG 通道实现**：
```python
class GraphRAGRetriever:
    def __init__(self, pg_entities, pg_rels, milvus_entity_embeds, llm):
        self.pg = pg_entities
        self.mv = milvus_entity_embeds
        self.llm = llm

    def retrieve(self, question: str, top_k=5) -> list[Doc]:
        # 1) LLM 抽 question 中的实体 mention
        mentions = self.llm.extract_mentions(question)
        # 2) PG 查 1-2 跳子图（实体 + 关系）
        subgraph = self.pg.fetch_subgraph(mentions, hops=2)
        # 3) Milvus `entity_embeddings` 取描述补全
        embeds = self.mv.search(mentions, k=10)
        # 4) 合并 → 社区摘要（可选）
        return [Doc(channel="graphrag", doc_id=..., snippet=..., score=...)
                for ... in subgraph + embeds]
```

**路由调用入口**：
```python
def answer(question: str) -> dict:
    # 1) LLM 意图路由
    decision = route_query(question)   # {"channel": "rag" | "graphrag"}
    # 2) 选对应 Retriever
    retriever = RAG_RETRIEVER if decision["channel"] == "rag" else GRAPHRAG_RETRIEVER
    docs = retriever.retrieve(question, top_k=5)
    # 3) 构造 prompt + 调 LLM
    answer = llm.generate(prompt_with(question, docs))
    # 4) 统一封装返回
    return {
        "answer": answer,
        "sources": [{"type": d.channel, "ref": d.ref, "snippet": d.snippet}
                    for d in docs],
        "channel_used": decision["channel"],
    }
```

**检索参数配置**：

| 参数                | 值  | 说明                            |
| ------------------- | --- | ------------------------------- |
| RAG 召回 top_k      | 20  | Milvus 初始召回                 |
| RAG 最终 top_k      | 5   | rerank 后送 LLM                 |
| GraphRAG 跳数       | 1-2 | PG 关系查询                     |
| GraphRAG 实体 top_k | 10  | Milvus `entity_embeddings` 召回 |
| GraphRAG 最终 top_k | 5   | 送 LLM                          |
| 相似度阈值          | 0.7 | 过滤低相关内容                  |

#### 3.3.3 图片检索技术

**检索流程**（v2 双通道融合）：
```
用户提问: "面心立方晶体的结构特点是什么？"
            │
            ▼
    ┌───────────────┐
    │ LLM 意图路由  │
    └───────┬───────┘
            │ 查事实 → RAG 通道
            ▼
┌──────────────────────────────┐
│  RAG 通道                     │
│  1) Milvus `chunks` 召回文本 │
│  2) rerank → 构造 chunk 上下文│
│  3) 同时召回关联图片：         │
│     - Milvus `image_embeddings`│
│     - 或：PG `illustrated_by`  │
│       边查图（GraphRAG 通道）  │
└──────────────┬───────────────┘
               │
               ▼
┌──────────────────────────────┐
│  合并排序，返回给用户         │
│  文字回答 + 图片URL列表       │
└──────────────────────────────┘
```

**多模态检索方案**（v2 简化）：

| 检索方式 | 技术                      | 说明                                               |
| -------- | ------------------------- | -------------------------------------------------- |
| 文本搜图 | Milvus `image_embeddings` | 用图片描述文本（caption + ai_description）搜索图片 |
| 标签搜图 | 关键词匹配                | 用 `caption` / `keywords` 过滤图片                 |
| 关联推荐 | GraphRAG 通道边查询       | 在 PG `relationships` 查 `illustrated_by` 边       |
| 图片搜图 | CLIP 图像Embedding        | 用相似图片搜索（可选，下期再做）                   |

**Milvus collection 全景**：
```
集合1: chunks（RAG 通道文本块）
  ├── chunk_id
  ├── document_id
  ├── page_num
  ├── text
  └── embedding (2048维, 智谱embedding-3, IVF_FLAT / COSINE)

集合2: image_embeddings（RAG 通道图片索引）
  ├── image_id
  ├── document_id
  ├── page_num
  ├── caption / ai_description
  ├── embedding (2048维, 智谱embedding-3)
  └── minio_path

集合3: entity_embeddings（GraphRAG 通道实体描述）
  ├── entity_id
  ├── name
  ├── type
  ├── description
  ├── embedding (2048维, 智谱embedding-3, IVF_FLAT / COSINE)
  └── doc_ids
```

**技术实现**：
```python
class ImageRetrievalService:
    def __init__(self):
        self.text_collection = MilvusCollection("chunks")        # RAG 通道
        self.image_collection = MilvusCollection("image_embeddings")
        self.graph_relations = PostgreSQLTable("relationships")  # 查 illustrated_by 边

    async def search_with_relations(self, query: str, top_k: int = 5):
        """带关联的图片检索（v2：用图谱边替代关联表）"""
        # 1. RAG 通道：向量检索文本块
        text_results = await self.text_collection.search(query, top_k=top_k)
        
        # 2. 向量检索图片描述
        image_results = await self.image_collection.search(query, top_k=3)
        
        # 3. 查关联表，补充高权重关联图片
        for chunk in text_results:
            relations = await self.relation_store.query(
                chunk_id=chunk.id, 
                min_weight=0.7
            )
            for rel in relations:
                if rel.image_id not in [r.image_id for r in image_results]:
                    image_results.append(await self.get_image(rel.image_id))
        
        return text_results, image_results
```

```python
from pptx import Presentation
from pptx.util import Inches, Pt

class PPTGenerator:
    def __init__(self, template_path: str):
        self.prs = Presentation(template_path)
    
    async def generate(self, topic: str, content: dict):
        """生成PPT"""
        # 封面页
        self.add_title_slide(topic)
        
        # 目录页
        self.add_toc_slide(content["outline"])
        
        # 内容页
        for section in content["sections"]:
            self.add_content_slide(section)
        
        # 参考来源页
        self.add_reference_slide(content["sources"])
        
        return self.prs
    
    def add_content_slide(self, section):
        """添加内容页"""
        slide = self.prs.slides.add_slide(
            self.prs.slide_layouts[1]
        )
        # 标题
        slide.shapes.title.text = section["title"]
        # 正文
        self.add_bullet_points(slide, section["points"])
        # 图片
        if section.get("image"):
            self.add_image(slide, section["image"])
```
